plainly: two host-level mismatches, both reproducible on unmodified main —
1. `scripts/build.sh` passes `--cpus=2` to docker; this host's kernel refuses it
   (`NanoCPUs can not be set, as your kernel does not support CPU CFS scheduler`).
   The identical container invocation with the memory cap (`--memory=6g`) intact
   was used instead: docker run --rm --memory=6g -e CARGO_TARGET_DIR=/target
   -v $PWD:/build -v $TARGET:/target -w /build --entrypoint /bin/bash
   rust:1-bookworm -c "cargo test -p stoffel-lobby -- --nocapture"
2. `-p lobby` matches no package; the package is named `stoffel-lobby`
   (crates/lobby/Cargo.toml), so `-p stoffel-lobby` is used.
