# Evidence bundle fixtures

Committed inputs for `stoffel-verify`, regenerated byte-for-byte by
`cargo run -p stoffel-verify --bin gen-fixtures` (run via `./scripts/build.sh`).

Every fixture carries a **real TDX quote** and its **real DCAP collateral** —
the `dcap-qvl` sample vendored by the StoffelVM fork at
`crates/stoffel-vm/src/tests/fixtures/dstack/tdx_quote.bin` — so each one that
reaches the quote step exercises the full Intel trust-chain verification. The
event log in each bundle is the captured w7 pod log
(`crates/stoffel-verify/tests/fixtures/pod_event_log.json`). The node keys,
job, joins and results are synthetic but properly signed (fixed seeds, see the
generator). The collateral's validity window is 2025-06-19..2025-07-19, so
verify these bundles with a pinned time inside it:

    stoffel-verify --at 1751328000 evidence/bundles/<name>.json

Expiry is a real check; at wall-clock time the same bundles fail with a quote
rejection (`CrlExpired`), which the CLI tests assert.

## Present

| fixture | what it proves | expected stderr |
|---|---|---|
| `bad-join-signature.json` | one join's signature does not verify under its declared key | `bad join signature` |
| `disagreeing-results.json` | both signatures are fine, the committee did not agree | `results disagree` |
| `tampered-measurement.json` | the quote verifies against the Intel root, but the measurement it attests is not the one the job's policy pins | `measurement not allowed` |
| `wrong-key-binding.json` | the quote verifies against the Intel root, but its real non-zero `report_data[8..40]` does not bind the node's pubkey | `key binding mismatch` |

## Absent, and why (issue #1 asks for six)

- `valid.json` — a bundle where every check passes needs a quote whose
  `report_data[8..40]` equals `blake3()` of a key the fixture author holds AND
  whose own event log replays onto its registers. Both properties are fixed by
  hardware at mint time: the binding is under the QE signature (finding a key
  whose blake3 equals a chosen 32-byte value is a preimage), and the log's fold
  must land exactly on the quote's RTMRs (the machine's own boot log). No TDX
  hardware is available to this repo's CI, and no captured quote+log pair with
  an L1 binding exists yet (that is fork task L1, not built). Producing this
  fixture requires one real dstack run of L1-enabled code; see the PR's
  BLOCKED section.
- `mutated-event-log.json` — reaching the event-log check requires the
  key-binding check to pass for the same node first, i.e. the same real L1
  quote. The check itself is exercised on real materials in the crate's tests:
  the pod event log replayed against the sample quote's registers fails with
  `event log rejected ... does not reconstruct RTMR`, and the same log against
  its own captured registers passes (see
  `the_real_pod_log_does_not_replay_onto_the_sample_quote_registers` and
  `the_real_pod_log_replays_onto_its_own_registers`).

`docker run --network none` transcripts of the four present fixtures are in
the PR body (Tier 2: the tool run against real captured artifacts).
